# Отчёт о benchmark (пилотный)

Дата прогонов: 07.10.2026. Модель: `claude-opus-5-5`. Данные: SYNDCAR (синтетический, CC BY 4.0).
Все результаты предварительные: выборка 40 снимков одного автомобиля, разметка severity/part/action
выполнена одним человеком дважды (разметки A и B); независимого второго разметчика не было.

## 1. Что измерялось

Сервис получает один снимок и возвращает JSON со списком повреждений (тип, деталь, серьёзность,
действие, уверенность, рамка). Ответ сравнивается с эталоном по правилу раздела 7 ТЗ: предсказание
и эталонное повреждение образуют пару, если IoU их рамок ≥ 0,5; сопоставление один к одному,
без учёта класса. Тип, серьёзность, деталь, действие и уверенность оцениваются только на парах.

| | dev | test |
|---|---|---|
| Снимков | 16 | 24 |
| Повреждений в эталоне | 98 | 142 |
| Съёмочные дни | 18–19.09.2024 | 17.09.2024 |

Рамки и типы повреждений взяты из разметки датасета, деталь определена автоматически и проверена
вручную, серьёзность и действие размечены вручную.

## 2. Порядок работы

Порядок подтверждается историей коммитов.

1. Выборка dev и test зафиксирована до экспериментов (seed 42).
2. Dev размечен, прогнан с промптом v2, ошибки разобраны.
3. Промпт изменён на v3 (только общие правила, см. `benchmark/prompt_changelog.md`), dev прогнан повторно.
4. Целевые пороги записаны в `benchmark/target_thresholds.json`.
5. Test размечен и закоммичен до прогона.
6. Test прогнан один раз с замороженным промптом v3. После этого промпт и разметка A не менялись.
7. После прогона выполнена повторная разметка B (dev и test) и посчитана зависимость метрик от разметки
   (раздел 4а). Таблица раздела 3 посчитана по разметке A и не пересчитывалась.

## 4. Разбор ошибок

**Пропуски — главная проблема.** На test 55 повреждений из 142 модель не отметила вообще (ни одна
её рамка их не пересекает), ещё 31 отмечено с рамкой, не дотянувшей до IoU 0,5. Пропуски связаны
с размером: из 71 повреждения площадью меньше 0,2% снимка найдено 13 (18%), из 66 повреждений
площадью 0,2–1% — 39 (59%). Снимки перед отправкой уменьшаются с ~3264 до 1568 пикселей по длинной
стороне, и мелкие повреждения, вероятно, становятся неразличимы. Прямо это не проверялось.

**Разбитые фары на test найдены хуже всего** (recall 0,216 против 0,652 на dev). Причина по имеющимся
данным не установлена; возможные объяснения — другие ракурсы в съёмочный день test и малый размер рамок.

**Модель почти не выдумывает повреждения.** Из 93 её рамок на test только 4 не пересекаются
ни с одним эталонным повреждением. Остальные 33 «лишние» — это реальные повреждения с неточной рамкой.
Поэтому precision 0,60 отражает точность локализации, а не ложные срабатывания.

**Тип определяется надёжно, если повреждение найдено:** 0,964 на парах. Низкий macro-F1 — следствие
пропусков, а не путаницы классов.

**Серьёзность модель определяет плохо, и измерить это точно не удаётся** — см. раздел 4а.

**Уверенность занижена.** Brier 0,129 при точности типа 0,964: в 10 парах модель дала уверенность
ниже 0,5, и во всех 10 тип был верен.

## 4а. Насколько метрики зависят от разметки

Серьёзность, деталь и действие размечал один человек. Чтобы оценить надёжность разметки, он разметил
dev и test повторно (разметка B): в тот же день, не открывая разметку A и ответы модели, с увеличением
снимков (разметка A делалась без увеличения). Это самосогласие, а не независимая проверка.

Согласие между разметками A и B (`compare_labels.py`):

| Поле | dev: согласие | dev: каппа Коэна | test: согласие | test: каппа Коэна |
|---|---|---|---|---|
| part | 99,0% | 0,99 | 100% | 1,00 |
| severity | 65,3% | 0,39 | 78,2% | 0,59 |
| action | 87,8% | 0,75 | 79,6% | 0,57 |

Точность модели на тех же парах при разных эталонах (`label_sensitivity.py`, промпт v3):

| Поле | Выборка | По разметке A | По разметке B | Где A и B совпали |
|---|---|---|---|---|
| severity | dev (45 пар) | 0,733 | 0,622 | 0,735 (34 пары) |
| severity | test (56 пар) | 0,464 | 0,536 | 0,500 (44 пары) |
| action | dev | 0,933 | 0,956 | 0,955 (44 пары) |
| action | test | 0,750 | 0,804 | 0,844 (45 пар) |
| part | dev | 0,844 | 0,822 | 0,841 (44 пары) |
| part | test | 0,857 | 0,857 | 0,857 (56 пар) |

Что из этого следует:

- **Деталь размечается надёжно**, и точность модели по детали (около 0,85) от разметки не зависит.
- **Серьёзность размечается ненадёжно:** один и тот же человек расходится сам с собой в 22–35% случаев
  (каппа 0,39–0,59). Правила раздела 9 ТЗ не дают однозначной границы между уровнями, особенно для трещин
  и разбитых фар.
- **При любом эталоне точность серьёзности на test — около 0,5** (0,46–0,54), порог 0,70 не достигнут.
  Результат dev (0,733) был оптимистичным: по разметке B он 0,622.
- **Действие:** на test 0,75–0,84 в зависимости от эталона.

## 5. Что дала настройка промпта

Изменения v2 → v3 касались только определений и общих правил. На dev точность типа выросла
с 0,750 до 0,956, серьёзности — с 0,325 до 0,733, Brier улучшился с 0,212 до 0,105. Recall вырос
мало (0,408 → 0,459): пропуски мелких повреждений формулировками не устраняются.

## 6. Ограничения

- Данные синтетические; результат не переносится на снимки реальных ДТП.
- Все снимки — один автомобиль. Dev и test разделены по съёмочным дням, но не независимы по автомобилю.
- Выборка пилотная: 16 + 24 снимка. Разница между dev и test в несколько пунктов находится
  в пределах шума, доверительные интервалы не считались.
- Серьёзность, деталь и действие размечены одним человеком дважды; независимой второй разметки,
  предусмотренной ТЗ, не было. Самосогласие по серьёзности низкое (раздел 4а), поэтому метрика
  серьёзности ненадёжна. Первая разметка делалась без увеличения снимков.
- Снимки уменьшаются перед отправкой; влияние этого на recall отдельно не измерялось.
- Test прогнан один раз; разброс между повторными прогонами модели не оценивался.

## 7. Выводы

1. Pipeline работает устойчиво: структурированный ответ, проверка формата, retry и fallback
   реализованы; на 56 вызовах все ответы были корректны с первой попытки.
2. Найденные повреждения модель классифицирует хорошо (тип 0,96, деталь 0,86), и почти не даёт
   ложных срабатываний.
3. Модель пропускает большую часть мелких повреждений (recall 0,39) и неточно ставит рамки.
   В текущем виде она не годится для полного перечня повреждений по одному общему снимку.
4. Серьёзность модель определяет верно примерно в половине случаев. Точнее измерить нельзя:
   сама разметка серьёзности воспроизводится плохо (каппа 0,39–0,59), правила нужно уточнять.

## 8. Что можно сделать дальше

- Уточнить правила серьёзности (измеримые признаки вместо «длинная», «глубокая») и провести
  разметку вторым, независимым человеком.
- Проверить влияние разрешения: отправлять снимок частями или с большим размером и сравнить recall.
- Повторить прогон test несколько раз, чтобы оценить разброс.
